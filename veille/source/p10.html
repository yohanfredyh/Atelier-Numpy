Partie 10

Données séquentielles et réseaux récurrents

Texte, parole, capteurs, cours financiers : dans une séquence, l'ordre porte l'information. Les réseaux récurrents (RNN) traitent les éléments un à un en maintenant une mémoire, l'état caché. Les LSTM et GRU ajoutent des portes qui contrôlent cette mémoire pour capturer des dépendances longues.

10.1 Séquences et séries temporelles

Définitions

Une séquence est une suite ordonnée $x_{1:T} = (x_1, x_2, \dots, x_T)$ avec $x_t\in\R^{F}$ ($F$ caractéristiques par pas de temps). L'ordre est essentiel : permuter les éléments change le sens. Une série temporelle est une séquence dont les observations sont indexées par le temps, généralement à intervalles réguliers (pas horaire, journalier…).

Contrairement aux données tabulaires, les observations ne sont pas indépendantes : $x_t$ dépend de son passé. La longueur $T$ peut aussi varier d'un exemple à l'autre (phrases de longueurs différentes).

DomaineExemple de séquenceTâche typique

Types de tâches séquentielles

  • Plusieurs-vers-un (many-to-one) : une séquence → une sortie (sentiment d'une critique, prévision de la valeur suivante).
  • Plusieurs-vers-plusieurs synchronisé : une sortie par pas (étiquetage morpho-syntaxique, segmentation).
  • Séquence-vers-séquence (seq2seq) : longueurs d'entrée et de sortie différentes (traduction, prévision multi-horizon).
  • Un-vers-plusieurs : une entrée → une séquence (légende d'image, génération musicale).

Composantes d'une série temporelle

On décompose souvent une série en $y_t = \underbrace{T_t}_{\text{tendance}} + \underbrace{S_t}_{\text{saisonnalité}} + \underbrace{\varepsilon_t}_{\text{bruit}}$ (modèle additif ; multiplicatif si l'amplitude saisonnière croît avec le niveau).

  • Stationnarité : moyenne, variance et autocorrélations constantes dans le temps. Beaucoup de méthodes la supposent ; on s'en approche par différenciation ($\Delta y_t = y_t - y_{t-1}$) ou par passage au logarithme.
  • Autocorrélation au décalage $k$ : mesure la dépendance entre la série et sa version retardée. Un pic à $k=12$ révèle une saisonnalité annuelle sur des données mensuelles. $$\rho(k) = \frac{\sum_{t=1}^{T-k}(y_t-\bar y)(y_{t+k}-\bar y)}{\sum_{t=1}^{T}(y_t-\bar y)^2}$$
  • Séries univariées ($F=1$) ou multivariées (plusieurs variables, plus des covariables connues à l'avance : calendrier, jours fériés, météo prévue).

10.2 Fenêtres temporelles et préparation des données

Un réseau de neurones apprend sur des couples $(X, y)$. Pour une série unique, on crée ces couples par fenêtres glissantes : on prend $L$ pas passés en entrée (lookback) et les $H$ pas suivants comme cible (horizon).

Construction des exemples $$X^{(n)} = (x_{n},\dots,x_{n+L-1}) \in \R^{L\times F}, \qquad y^{(n)} = (y_{n+L},\dots,y_{n+L+H-1}) \in \R^{H}$$

Avec un glissement de 1, une série de longueur $T$ donne $N = T - L - H + 1$ exemples, empilés en un tenseur $(N, L, F)$ : format batch_first attendu par nn.RNN, nn.LSTM, nn.GRU.

import numpy as np

def make_windows(series, L, H, target_col=0):
    """series : (T, F) -> X : (N, L, F), y : (N, H)"""
    T = len(series)
    X = np.stack([series[i:i + L] for i in range(T - L - H + 1)])
    y = np.stack([series[i + L:i + L + H, target_col] for i in range(T - L - H + 1)])
    return X.astype(np.float32), y.astype(np.float32)

# 1) découpage chronologique AVANT tout calcul de statistique
n = len(data); i_tr, i_va = int(0.7 * n), int(0.85 * n)
train, val, test = data[:i_tr], data[i_tr - L:i_va], data[i_va - L:]   # recouvrement de L pas pour l'historique
# 2) normalisation ajustée sur l'entraînement uniquement
mu, sd = train.mean(axis=0), train.std(axis=0)
train, val, test = [(d - mu) / sd for d in (train, val, test)]
# 3) fenêtres
X_tr, y_tr = make_windows(train, L=48, H=24)

Choix et étapes clés

  • Longueur $L$ : doit couvrir les dépendances utiles (au moins une période saisonnière). Trop courte : information manquante ; trop longue : bruit, coût, gradients difficiles pour un RNN.
  • Normalisation : standardisation ou min-max, ajustée sur l'entraînement seulement (sinon fuite d'information du futur). On inverse la transformation pour exprimer les erreurs dans l'unité d'origine.
  • Caractéristiques temporelles : encodage cyclique de l'heure ou du mois, $\big(\sin\frac{2\pi h}{24}, \cos\frac{2\pi h}{24}\big)$, qui place 23 h à côté de 0 h ; retards (lags) ; moyennes mobiles calculées uniquement avec le passé.
  • Valeurs manquantes : interpolation, report de la dernière valeur (forward fill), éventuellement un indicateur binaire de valeur manquante.
  • Prévision multi-pas : stratégie directe (le modèle sort les $H$ valeurs d'un coup) ou récursive (on prédit $t+1$, on réinjecte la prédiction, etc. ; les erreurs s'accumulent).

Séquences de longueur variable (texte)

Pour regrouper des phrases de longueurs différentes dans un lot, on les complète (padding) avec un token spécial jusqu'à la longueur maximale du lot, et on indique au réseau d'ignorer ces positions : masque, ou nn.utils.rnn.pack_padded_sequence qui évite au RNN de traiter le remplissage.

10.3 Réseaux récurrents (RNN)

Un MLP traite une entrée de taille fixe et n'a aucune mémoire. Un réseau récurrent lit la séquence pas à pas et met à jour un vecteur interne, l'état caché $h_t\in\R^{d_h}$, qui résume tout ce qui a été vu jusque-là. La même cellule, avec les mêmes poids, est appliquée à chaque instant : c'est le partage des poids dans le temps (comme la convolution partage ses poids dans l'espace).

Équations du RNN simple (Elman, 1990) $$\boxed{\;h_t = \tanh\!\big(W_{xh}\,x_t + W_{hh}\,h_{t-1} + b_h\big)\;} \qquad \hat y_t = W_{hy}\,h_t + b_y$$

avec $W_{xh}\in\R^{d_h\times F}$, $W_{hh}\in\R^{d_h\times d_h}$, $W_{hy}\in\R^{d_{out}\times d_h}$ et $h_0 = 0$. Nombre de paramètres de la cellule : $d_h(F + d_h) + 2d_h$ dans PyTorch (deux vecteurs de biais), indépendant de $T$.

Pour une tâche many-to-one (classification, prévision), on n'utilise que le dernier état $h_T$ (ou un pooling sur tous les $h_t$). Pour une tâche synchronisée, on utilise chaque $\hat y_t$.

import torch.nn as nn

rnn = nn.RNN(input_size=8, hidden_size=64, num_layers=1, batch_first=True)
x = torch.randn(32, 48, 8)        # (N, L, F) : 32 fenêtres de 48 pas, 8 variables
out, h_n = rnn(x)
print(out.shape)                  # (32, 48, 64) : h_t pour chaque pas t
print(h_n.shape)                  # (1, 32, 64)  : dernier état h_T (par couche)

Variantes

  • RNN empilé (num_layers=2 ou plus) : la séquence des $h_t$ d'une couche est l'entrée de la suivante ; représentations plus abstraites.
  • RNN bidirectionnel (bidirectional=True) : un RNN lit de gauche à droite, un autre de droite à gauche ; on concatène $[\overrightarrow{h_t};\overleftarrow{h_t}]$. Utile quand toute la séquence est disponible (texte), interdit en prévision (cela reviendrait à regarder le futur).
  • Encodeur-décodeur (seq2seq) : un RNN encode la source en un vecteur, un second RNN génère la cible ; ancêtre direct des Transformers (partie 11).

10.4 État caché et dépendances temporelles

L'état caché est une mémoire compressée de taille fixe : $h_t = f(h_{t-1}, x_t)$ dépend récursivement de tout le passé $x_{1:t}$. Il doit encoder ce qui sera utile plus tard (le sujet d'une phrase pour accorder un verbe vingt mots après, la tendance récente d'une série…). Une dépendance à long terme relie une sortie à une entrée lointaine ; c'est là que le RNN simple échoue.

Rétropropagation dans le temps (BPTT)

On entraîne le RNN déplié comme un réseau profond : la perte totale $\mathcal{L}=\sum_t \mathcal{L}_t$ est rétropropagée à travers tous les pas de temps, et les gradients des poids partagés s'additionnent sur les instants. Le signal reliant l'instant $t$ à un instant antérieur $k$ fait intervenir un produit de jacobiennes :

Gradients évanescents et explosifs $$\frac{\partial h_t}{\partial h_k} = \prod_{i=k+1}^{t} \frac{\partial h_i}{\partial h_{i-1}} = \prod_{i=k+1}^{t} \diag\!\big(1 - h_i^{2}\big)\, W_{hh}$$

En simplifiant, la norme de ce produit se comporte comme $\lambda^{t-k}$, où $\lambda$ dépend de la plus grande valeur singulière de $W_{hh}$ et de la dérivée de $\tanh$ ($\le 1$) :

  • $\lambda < 1$ : le gradient s'évanouit exponentiellement, le réseau n'apprend pas les dépendances longues (en pratique au-delà de 10 à 20 pas) ;
  • $\lambda > 1$ : le gradient explose, entraînement instable (pertes NaN).

Remèdes

  • Écrêtage du gradient (gradient clipping) contre l'explosion : si $\lVert g\rVert > \tau$, $g \leftarrow \tau\, g/\lVert g\rVert$. En PyTorch : torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0) entre backward() et step().
  • BPTT tronquée : on rétropropage sur des segments de longueur limitée (coût mémoire maîtrisé).
  • Initialisation orthogonale ou identité de $W_{hh}$, normalisation.
  • Contre l'évanouissement, la vraie solution est architecturale : des cellules à portes (LSTM, GRU) qui créent un chemin où l'information et le gradient circulent presque sans atténuation.

10.5 Introduction aux LSTM et GRU

LSTM — Long Short-Term Memory (Hochreiter & Schmidhuber, 1997)

Le LSTM ajoute à l'état caché $h_t$ une cellule mémoire $c_t$, une « autoroute » de l'information mise à jour de façon additive. Trois portes à valeurs dans $[0,1]$ (sigmoïdes) décident, composante par composante, quoi oublier, quoi écrire et quoi exposer.

Équations du LSTM $$\begin{aligned} f_t &= \sigma\big(W_f\,[h_{t-1}, x_t] + b_f\big) && \text{porte d'oubli}\\ i_t &= \sigma\big(W_i\,[h_{t-1}, x_t] + b_i\big) && \text{porte d'entrée}\\ \tilde c_t &= \tanh\big(W_c\,[h_{t-1}, x_t] + b_c\big) && \text{contenu candidat}\\ c_t &= f_t \odot c_{t-1} + i_t \odot \tilde c_t && \text{mise à jour de la mémoire}\\ o_t &= \sigma\big(W_o\,[h_{t-1}, x_t] + b_o\big) && \text{porte de sortie}\\ h_t &= o_t \odot \tanh(c_t) && \text{nouvel état caché} \end{aligned}$$

$[h_{t-1},x_t]$ : concaténation ; $\odot$ : produit élément par élément ; $\sigma(z)=1/(1+e^{-z})$.

Pourquoi ça marche : $\frac{\partial c_t}{\partial c_{t-1}} = \diag(f_t)$ (en ignorant les dépendances indirectes). Si la porte d'oubli reste proche de 1, le gradient traverse de nombreux pas presque intact : c'est le carrousel d'erreur constante. Le réseau apprend lui-même quand retenir et quand effacer. Astuce courante : initialiser $b_f$ à 1 pour favoriser la mémorisation au début de l'entraînement.

GRU — Gated Recurrent Unit (Cho et al., 2014)

Version simplifiée : pas de cellule séparée, deux portes seulement.

Équations du GRU $$\begin{aligned} z_t &= \sigma\big(W_z\,[h_{t-1}, x_t] + b_z\big) && \text{porte de mise à jour}\\ r_t &= \sigma\big(W_r\,[h_{t-1}, x_t] + b_r\big) && \text{porte de réinitialisation}\\ \tilde h_t &= \tanh\big(W_h\,[\,r_t\odot h_{t-1},\, x_t] + b_h\big) && \text{état candidat}\\ h_t &= (1 - z_t)\odot h_{t-1} + z_t \odot \tilde h_t && \text{interpolation} \end{aligned}$$

La porte $z_t$ joue à la fois le rôle des portes d'oubli et d'entrée du LSTM. (PyTorch utilise la convention inverse : $h_t=(1-z_t)\odot\tilde h_t + z_t\odot h_{t-1}$ ; c'est équivalent.)

class LSTMForecaster(nn.Module):
    def __init__(self, n_features, hidden=64, horizon=24, layers=2, dropout=0.2):
        super().__init__()
        self.lstm = nn.LSTM(n_features, hidden, num_layers=layers,
                            batch_first=True, dropout=dropout)
        self.head = nn.Linear(hidden, horizon)          # stratégie directe : H sorties

    def forward(self, x):                               # x : (N, L, F)
        out, (h_n, c_n) = self.lstm(x)                  # h_n : (layers, N, hidden)
        return self.head(h_n[-1])                       # dernier état de la dernière couche -> (N, H)

loss = nn.MSELoss()(model(xb), yb)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # sécurité anti-explosion
optimizer.step()
Positionnement actuel

Pour le texte, les LSTM/GRU ont été largement remplacés par les Transformers (partie 11), parallélisables et meilleurs sur les dépendances longues. Ils restent compétitifs pour des séries temporelles de taille modeste, le traitement en flux (streaming, coût constant par pas) et l'embarqué. Des architectures récurrentes modernes (state space models comme Mamba, xLSTM) reprennent ces idées à grande échelle.

10.6 Évaluation avec un découpage chronologique

Le découpage aléatoire train/validation/test, standard pour des données i.i.d., est incorrect pour une série temporelle : le modèle s'entraînerait sur des observations postérieures à celles qu'il doit prédire. C'est une fuite d'information (look-ahead bias) qui donne des scores optimistes, impossibles à reproduire en production où l'on ne connaît que le passé.

Principe

Toujours entraîner sur le passé, valider sur un futur proche, tester sur un futur plus lointain : $t_{train} < t_{val} < t_{test}$. Toutes les étapes ajustées sur les données (normalisation, imputation, sélection de variables) le sont sur l'ensemble d'entraînement seul.

Validation glissante (walk-forward / backtesting)

Une seule coupure peut tomber sur une période atypique. On répète donc l'évaluation sur plusieurs origines successives : fenêtre d'entraînement croissante (expanding) ou glissante de taille fixe (rolling, adaptée si la dynamique évolue), puis on moyenne les scores. On peut laisser un écart (gap) entre entraînement et validation quand les fenêtres d'entrée se chevauchent ou que la cible est connue avec retard.

from sklearn.model_selection import TimeSeriesSplit

tscv = TimeSeriesSplit(n_splits=4, test_size=500, gap=24)   # fenêtre croissante + écart
for k, (idx_tr, idx_va) in enumerate(tscv.split(X)):
    model = build_model()
    fit(model, X[idx_tr], y[idx_tr])                         # les indices de validation sont toujours postérieurs
    scores.append(evaluate(model, X[idx_va], y[idx_va]))
print(np.mean(scores), np.std(scores))

Références naïves et métriques

Un modèle profond n'a de valeur que s'il bat des références simples :

  • Persistance : $\hat y_{t+1} = y_t$ ; naïf saisonnier : $\hat y_{t+h} = y_{t+h-m}$ ($m$ = période) ; moyenne mobile ; modèles statistiques (ARIMA, lissage exponentiel).
Métriques de prévision $$\text{MAE} = \frac1n\sum_t |y_t-\hat y_t| \qquad \text{RMSE} = \sqrt{\frac1n\sum_t (y_t-\hat y_t)^2} \qquad \text{MAPE} = \frac{100\%}{n}\sum_t \left|\frac{y_t-\hat y_t}{y_t}\right|$$ $$\text{MASE} = \frac{\text{MAE}_{\text{modèle}}}{\frac{1}{T-m}\sum_{t=m+1}^{T}|y_t-y_{t-m}|} \qquad (\text{MASE} < 1 \;\Leftrightarrow\; \text{meilleur que le naïf saisonnier})$$

MAE : robuste, dans l'unité de la cible. RMSE : pénalise davantage les grosses erreurs. MAPE : en pourcentage, mais indéfini si $y_t=0$. MASE : comparable entre séries.

Erreurs classiques
  • Mélanger les fenêtres avant le découpage (shuffle=True sur l'ensemble complet). Le mélange est permis à l'intérieur de l'ensemble d'entraînement, une fois le découpage fait.
  • Normaliser avec la moyenne de toute la série, ou calculer des moyennes mobiles centrées (qui utilisent le futur).
  • Utiliser comme variable d'entrée une information qui ne sera pas disponible au moment de la prévision.
  • Évaluer une prévision récursive avec les vraies valeurs réinjectées (teacher forcing) au lieu des prédictions.
À retenir — Partie 10
  • Dans une séquence, l'ordre porte l'information et les observations sont dépendantes (tendance, saisonnalité, autocorrélation).
  • Les fenêtres glissantes transforment une série en exemples $(N, L, F)\to(N, H)$ ; la normalisation est ajustée sur l'entraînement seul.
  • RNN : $h_t=\tanh(W_{xh}x_t+W_{hh}h_{t-1}+b)$, poids partagés dans le temps, entraînement par BPTT.
  • Le produit de jacobiennes provoque l'évanouissement ou l'explosion des gradients ; l'écrêtage traite l'explosion.
  • LSTM (3 portes + cellule additive) et GRU (2 portes) capturent les dépendances longues.
  • Évaluation : découpage chronologique, validation glissante, comparaison aux références naïves, MAE/RMSE/MASE.
